real differences in newcore
  1. a request that throws runs no rounds (scheduler.ts request(): rounds drain
     only after fn() returns). a handler's changes before its throw leave readers
     due until some later request. old suite ran them before returning.
     fix: drain in the finally.
  2. a write with no patches marks nobody. old suite marked readers.  (decide)
  3. a path-started process's first run has no program in its agent: runAgent
     is built before the finder sets p.program. later runs fine.  (bug)
  4. a killed ephemeral node's id stays in its list, reads back pending.
     old suite removed it.  (decide)
  5. the code finder takes the path as given; the old one searched up from the
     process's place. the host's job now, probably fine.

also: status is its own first version (because place "status") and is mirrored
in change.actor.code; the adapter reshaped it back to old form without trouble.
