* A contributor (mine)
#+begin_src ts
// where a walk has got to: the path so far, and the id it is at (none: nothing there yet)
type Where = { readonly path: Path; readonly id: Id | undefined }

type Contributor = {
	// what is at where + name; none: undefined
	step(where: Where, name: string, reads: Reads): Id | undefined
	// the names it knows directly under where
	names(where: Where, reads: Reads): string[]
}

// what a contributor reads through: places' reads over table parts, and track for any other key
type Reads = {
	read(part: Key, id: Id, path?: Step[]): unknown
	keys(part: Key, id: Id, path?: Step[]): string[]
	track(key: unknown): void
}
#+end_src
- a contributor reads only through =reads=, and marks what it owns with the scheduler's =mark= when
  it changes (a table write already does, through commit)
- its writes are its own: children keeps =place=, =unplace=, =rename=, =move=; processes =start=,
  =stop=

// children: uses the id, never the path
const children: Contributor = {
	step: ({ id }, name, r) => id === undefined ? undefined : asId(r.read("children", id, [name])),
	names: ({ id }, r) => id === undefined ? [] : r.keys("children", id),
}

// processes: uses the path, never the id. rows on the root's process part, a trie by path: a
// level a map, a leaf the process's id. a start marks only its own path. a process's own things
// (its subprocesses too) are inside its node, so nothing sits under a leaf:
//   (process, R) = { work: { clock: "proc:7f3a", timer: "proc:91bc" }, dev: { clock: "proc:44d0" } }
const processes = (root: Id): Contributor => ({
	step: ({ path }, name, r) => asId(r.read("process", root, [...path, name])),  // a map: none here
	names: ({ path }, r) => r.keys("process", root, path),
})
#+end_src

* The cache
- an entry per path someone reads: ={ id, key, read: keys }=. =key= is the one thing a reader
  tracks; =read= is every key the contributors read while working it out
- worked out when first read, there and then, untracked by the reader's run (the reader tracks only
  =key=); a fresh entry is reused
- dropped when a key in its =read= is marked: the cache listens to the scheduler's =onMark= and keeps
  a map from each key to the entries that read it. dropping an entry marks its =key=, inside the same
  write, so readers rerun and are due by the writer's run
- dropped when nobody tracks its =key= (=onUntrack=)
- an entry for a path reads the entry for its parent (one step at a time), so dropping a parent
  drops what was built on it

* From the review (playground/union-check, cache.ts, 47 tests; mine to fold in)
- works: fresh in the same tick; first read in one run; no computers, no causes; shadowing; a
  start reruns nothing; 300 paths and processes: first pulse 5-14 ms (places 3-4, computers 37-67)
- the bug: an entry read a spot a plain places reader also read; that reader went, places let the
  spot go, the entry was never dropped again. so the cache owns letting spots go (places' release)
- per key, a count of runs and of child entries reading it: an entry goes when both are 0 (a parent
  is read by its children's entries, never by a run)
- recording what a step read: places made with a wrapped track (wiring, no scheduler change)
- equal cut: on a drop, work the entry out again and mark its key only if the answer changed
- names: one name, one listing (from: the first contributor that gives it); stop removes levels left
  empty
- untracked reads (a host's, an effect's act) leave entries until a write drops them: open
- every asker's cache hears every mark: open (one shared cache per root, or per mark key)
