#+title: Reviews of LOADING.tex, 2026-10-07 (Acton, Kleppmann, Kelley lenses)

* Where all three agree
- A saved version is an immutable, content-hashed object (Kleppmann:
  {tree, parents, by, why}; Acton: one built blob, identity = content hash;
  Kelley: build.zig.zon-style manifest pinned by hash). Heads are
  provenance. Full hash in URLs, short only for display.
- Derived data (builds, caches, reader values) lives outside the source
  folder, in a content-addressed store keyed by code version, target,
  compiler and what was read. Installing into a folder is a separate,
  explicit write.
- Building happens outside the loader, as a process running one compiler
  that takes the target as input. Loaders don't chain.
- The floor needs ended(why), and closed, typed reasons (stop: requested,
  replaced, unplaced, parent, host; ended: exited, failed, killed, lost;
  refused: needs target / signing / permission / reflash).

* Acton (data-oriented)
- Definitions are an org chart; rewrite as a data table: input, output,
  size, lifetime, rate, owner per stage.
- "Loader" is resolve / build / load / instantiate / pump / release, at
  different rates. Split load(artifact) (once per hash per host) from
  start(code, processes[]).
- One program, many processes: on a chip, one wasm instance per program
  with processes as rows; in a browser one worker per trust domain.
- Name the common case (same-thread formula, firmware table) and make it a
  direct call. Give news a rate; batch per buffer or round.

* Kleppmann (local-first, data systems)
- A version must mean the same on every device; "newer" is "descends
  from"; two newest are sides, never chosen silently.
- Version skew is the missing problem: versions coexist over shared nodes;
  translate on read; the agent's program identity is a schema tag; no
  swap-time migration of shared nodes.
- A save is a deploy: gate switching. Actions are at-least-once and need an
  idempotency key.
- Properties P1-P5: determinacy, isolation, fence, cache soundness,
  agreement.

* Kelley (Zig)
- A target is a structured value matched by a relation (arch, CPU model
  and features, OS and version range, ABI/api and version, object format),
  not a string. Vendor is noise. Board and host permissions are separate
  from the target. Hosts publish their target as a node.
- Close the floor's control flow: start may finish later; exactly one ended
  per start; no api call re-enters user code; a write through a revoked
  interface returns an error.
- Memory and means are parameters: a per-process budget at start; every
  write, add and read can fail with full; a bounded queue from world to
  graph (mandatory on chips; ISRs can't write the graph).
- Swap is stop(replaced) + start under the same pid, at a safe point
  between runs; not a stage.
- Cuts: client = interface lifetime; transform = reader; declared/added
  units = one add against a budget; resolve = a host match from data.
