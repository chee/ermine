A proposal to react to. Nothing built.

* The idea in six lines
- A path from a root is itself an id: =pathid(R, ["work"])=. Opaque to the table, like any id.
- What is *of a path* (processes, in-memory items, local overlays) is a row in a part keyed by that
  path id. Nothing is written on the folder's node, nothing on the root's node.
- A process posts its own name there when it starts and takes it out when its scope goes
  (Erlang's =register=, Plan 9's =/srv=). The table is the registry; no map beside the graph.
- The walk reads one more key per step: =(process, pathid(root, names so far))= before
  =(children, folder id)=. The ephemeral wins. Tracked, watched, drawn like any read.
- Path ids are never saved (a symbol: "symbols aren't saved"). Sent by an ephemeral library as
  =(root, names, patches, until)=; a receiver who lacks that root never matches them.
- What is *of an id* (presence, a shared ghost) keys by the node's id, as chee's
  =table.get("ephemeral", workFolder)= does. Same ephemeral library, different key.

Three parts, not one "ephemeral", *decided*: process / presence / overlay differ in what a read
does with them (walk a name / nothing / patch the value), their anchor and who writes.

* The walk, changed (filesystem/places, not core)
#+begin_src ts
// walk from a path, not an id: a step needs the names so far to make the path id
function* walk(path: Path, from: Path = []): Generator<Member> {
	const names = [...from]
	let at: Id | undefined = find(from)                       // undefined: the folder isn't there
	for (const name of path) {
		const live = pathid(root, names)
		tell(paths.spot(first("process"), live, [name]))
		if (at !== undefined) tell(paths.spot(first("children"), at, [name]))
		const p = child(table.get("process", live), name)
		const id = p ?? (at && child(table.get("children", at), name))
		if (id === undefined) return
		yield { name, id, from: p ? "process" : "children" }    // reads are lists: from says why
		names.push(name), at = id
	}
}
#+end_src
- cost: one extra spot per step, a read of a key that is usually empty. No trie, no index.
- =entries(path)=: both ids at a name with their =from=, *decided* ("a separate function like
  entries(path)"). =list=/=members=: process names first, then saved names not shadowed.
- =lookup(names, from)= is unchanged in shape: it walks to =from= once, then tries each place on
  the route nearest first; each try is a =walk= from that place's path, so it sees process rows.
- a walk on through a folder that isn't there (=/dev= with no saved =dev=): =at= undefined, process
  rows still read. *decided* 10-14: "it's okay it doesn't exist, we mark it as a read".

* Starting a process (a library: ermine/process, mine)
#+begin_src ts
export function start(w: World, at: Path, program: Program) {
	const names = at.slice(0, -1), name = at.at(-1)!
	const scope = w.scheduler.createScope([["process", at]])       // the path is an info pair
	const id = crypto.randomUUID()                                  // the scope's node
	w.scheduler.runWithScope(scope, () => {
		const header = createChangeHeader(w.scheduler)
		w.table.add("children", id, createEntry({}, header))        // its inner stuff
		const live = pathid(w.places.root, names)
		let row = w.table.get("process", live)
		if (!row) w.table.add("process", live, row = createEntry({}, header))
		w.places.commit(place(row, name, id, header))               // already-there: refused
		w.scheduler.registerTeardown(scope, () =>
			w.places.commit(unplace(row!, name, createChangeHeader(w.scheduler))))
		w.status.give(/* computers made inside */, id)
		program({ scope, id, at })                                  // setup once
	})
	return { scope, id, at, stop: () => w.scheduler.teardown(scope) }
}

- *decided*: a process is a scheduler scope with a path; scopes get table nodes; the node sits at its
  cwd; its own =start= and =stop=; placing never starts it; unique and local.
- *mine*: unique per address falls out of =place='s already-there (prog-build's need).
- *open*: whether a second =start= at a taken name refuses, replaces, or gets "clock+".

* Programs and processes
- *decided*: "a process is an instance of a program. a program is a node that declares what it
  needs and provides."
- a program node is saved content, placed in a folder as any node: at /work/clock, id C:
  =value=: its code (or a reference to it); =attributes=: ={needs: […], provides: […]}=;
  =children=: what it connects to (its fixtures, a default =on/=).
- a process node P is an instance: =value=: what setup returned (*decided* "setup once → value");
  =attributes=: ={program: C, "ermine.computer.status": …}=; =children=: its inner stuff
  (=on/reset=, parts, pipes). P sits at the program's path through the process row, shadowing C
  (the ephemeral wins). =entries(["work","clock"])= gives both: the instance and its program.
- needs are found by =lookup= from the place, nearest first; which device runs it, *decided*:
  "whichever device the closest valid loader is on". A loader is a program that provides
  "loader"; the device that holds the nearest valid one posts the row, keyed by its path from the
  shared root. So the same rule that finds a provider decides where a process lives.
- *lean* kept as is: value is content, attributes metadata, children what it connects to; a node is
  the three. The process row is not a fourth part on the node: it is of the path, under the path
  id. No folder kind: P has a value and children like any node.

* Cases

** a process started at /work/clock
- rows: =(process, pathid(R, ["work"])) = {clock: P}=; =(children, P) = {}=; =(children, W)= untouched.
- =get(["work","clock"])= → P (from: process). If a saved =clock= (a program file C) sits in W,
  the read is =[{P, process}, {C, children}]=: the process shadows its program. *decided*: "the
  ephemeral wins".
- *mine*: "." = P, a bare name = /work/x, ".." = /: the process's info pair carries =at=, and its
  walks start from =["work","clock"]=, =["work"]= or =[]= (plan() in path.ts).

** ./on/reset under it
- =(children, P) = {on: O}=, =(children, O) = {reset: H}=, H a node holding the handler.
- a plain children walk once inside P. *decided*: "a process's inner stuff is inside the process".
  P, O, H are reachable only through a path id, so pack never meets them.

** list(/work)
- =readKeys("process", pathid(R, ["work"]))= ∪ =readKeys("children", W)=: =["clock", "notes", …]=.
- the first read is a keys spot on the path id; =place=/=unplace= on the row mark it, so a run
  listing /work reruns when clock starts or stops. *decided* check ✓.

** lookup by bare name from inside /work
- a process at /work/clock asks =lookup(["clock"], ["work","clock"])=: tries =["work","clock"]=
  (P's children: no), then =["work"]= (process row: yes) → =["work","clock"]=. Nearest first, the walk
  to where you are made once (lib.ts as today). Nothing walks from the root for a name. *decided*:
  "nearest wins for lookup".

** a second device that mounted my "/"
- two shapes, chee picks:
  1. my devices share one root document R (OS card memory: "root becomes a device-id document").
     The phone's rows arrive at the same key =(process, pathid(R, ["work"]))=, change.actor = the
     laptop; its walk finds clock at /work/clock with from: {process, actor: laptop}. No rewriting.
  2. the phone mounts R under its own root R2 at /laptop: a =mount= library rebases rows as they
     arrive: =(root R, names) → pathid(R2, ["laptop", …names])=. Plan 9's =import=: the client
     says where the remote tree lands.
- *decided*: visible "while the ephemeral channel says it's there": each row has =until=; the
  owner renews; the receiver sweeps past it (Yjs awareness: 30 s; chee: "gone works with pigeons
  if the heartbeat is long"). *mine*: =until= on the row, not a channel fact, so pigeons work.

** a collaborator who has only /work shared
- they hold W, not R. My rows are keyed =pathid(R, …)=: never sent to them (not their root's topic),
  never matched by their walk. They see /theirs/work without clock. *lean* ✓: "idk if they see it,
  you'd see it if you mounted my whole /".
- to offer a process to a folder's readers, I would post it *of the id*: =(process, W) = {clock: P}=.
  Strain: that puts my table on a node I may have mounted ("it shouldn't get my tables"). *open*:
  allowed as an explicit offer, or never.

** a cursor in a shared doc
- =(presence, D) = {"juno-pad": {value: {cursor: [12, 40]}, until}}=. Of the id: wherever D is
  mounted. chee's shape, *lean* ✓, with =upsert(part, id, who, value, ttl)= in the ephemeral lib.
- never saved, though D is: *needs the per-part policy* (below). Sent on D's topic
  (Automerge: ephemeral rides the doc's peer set).

** a drag ghost
- local: =(overlay, pathid(R, ["board","cards"])) = {me: {patches, on: C, at: v, until}}=; a read of
  the value at that path applies the patches over C's value. The patch node, *decided*: "stores what
  version it was a patch for".
- shared: =(overlay, C) = {juno: {…}}=; collaborators' reads of C apply it, with from: {overlay,
  juno}. The chooser is the sender: of a path (mine only) or of the id (shared).
- strain: overlays need path-aware value reads: a lib =read(places, path, …)= that walks, then
  applies overlay rows; =readValue(part, id, path)= stays dumb.

** /dev/clock on this device
- the host starts a driver process at /dev/clock: =(process, pathid(R, [])) = {dev: Dv}=,
  =(process, pathid(R, ["dev"])) = {clock: K}=. No saved =dev= needed. A driver is a program:
  "programs may not be special". Inferno: =#c= enters the tree only by a bind.

** a boxed process with its own "/"
- a box is a places made with another root, *decided*. Two kinds, chee picks:
  1. box = a path under R (chee: "a box is a path", found again on each walk): its places keeps
     root R and a prefix; =pathid(R, [...prefix, ...names])=: what it places shows outside at
     /work/… too.
  2. box = its own node B as root: =pathid(B, names)=: its placements and in-memory items are
     private to it (Plan 9 =RFCNAMEG=, Fuchsia: only what you were handed is reachable). The
     inspector lists boxes as roots.
- =..= at "/" is "/" (plan.ts), so neither climbs out.

** saving (what pack sees)
- pack walks =children= from the root: path ids are symbols and never under children, so P, O, H
  and every process row are never reached. =/work='s saved children never change. ✓
- not enough for of-an-id rows: =(presence, D)= sits on a saved node. So the *open* question
  becomes needed: parts carry a side's policy, *mine*: =/system/tables/<part>= with
  ={save: false, send: "ephemeral"}= for process/presence/overlay; value/attributes/children
  built in. "something might be permanent on their side and ephemeral on mine" = each side's table.
- pack picks parts by that policy, not the caller's triples. *mine*, one change in pack.

const pipe = start(w, [...at, "pipes", "ab"], ({ scope }) => {

- patches pass through: =watchPath= hands each write's patches as it lands, nothing kept.
  *decided* ("okay so we do callbacks"). The pipe is a process: it has a path (./pipes/ab), a
  node, a status attribute for its errors, and ends with its parent.
- strain: a write after an await is from the scope, not a run: no cause, no loop cut. Same as every
  handler today.

** the process stopping
- =teardown(scope)=: the registered teardown writes =unplace(row, "clock")=, =commit= marks the
  process spot (list reruns, get gives C or nothing) and tells watches; the ephemeral lib sends the
  patch and the receivers' sweep drops it past =until= if the send is lost. P's entries:
  =table.del(P)= by the process lib, or left unreachable. *decided*: a placement ends when its
  placer ends.
- =move= of /work while clock runs: the row is keyed by the old path and stays there (a symlink
  breaks the same way). *open*: unplace = kill, or the process follows. Keying by id would make it
  follow; keying by path is *decided*.

* Where it strains
- "the walk needs its path": it does, to make the path id. It already iterates names; only
  =walk(path, from: Id)= becomes =walk(path, from: Path)=. =members(path)= has the path.
- a path id is a new kind of id. Nothing in the table knows, but C needs an interned key and the
  wire needs =(root, names)=. Encoding, *open*.
- rows at a path id are "of a path" but there is still a place they live: the table under a key
  nobody can reach by walking. Is that "in the graph"? They are entries with changes, patched,
  tracked, watched, drawable. Not reachable from a root by children: so the inspector draws them
  through the walk (as it draws /work/clock), not by listing ids.
- a renamed folder orphans its rows (above). Plan 9 has the same: a bind is by name.
- "every node needs to be able to have a layout": here every node can be a root and layouts are
  rows keyed from it. No layout part on the node itself.
- the offer-to-folder case puts a part on a mounted node: against "it shouldn't get my tables",
  unless an explicit offer is allowed.
