#+title: sources, a first try

An experiment from the sketch sources-2026-10-22 (ermine-plans): a holder, a link, a value mirror,
and the smallest history to name writes. Nothing here is decided. Each line below is my pick, where
the sketch left a choice open; any of them can change.

* picks (mine, not decided)
- a write: node, part, parents, patches, change (the header without its op); its name the blake3 of that, as canonical CBOR, in hex
- a named write is read back from its encoding, sharing nothing (places' children change in place)
- a fact with something no encoding has (a function, a symbol) is not named; history counts it in skipped
- only string ids are recorded
- an entry taken out with no scope open (no change from places): history makes its change, time now, actor null
- history is made before the graph's first write; a value written before it has no base
- writes made at once: the part's whole history played again, parents first, ties by the lower name; the value lands as one patch at the root
- in the playing, a write whose patches don't apply there is passed over
- a write lands with its own change (its actor, time and site), not the landing device's
- history's echo: facts at the node and part being landed, while it lands, are its own
- every holder refuses a write misnamed or missing a parent, so since gives parents first
- put gives one outcome per write, in order
- a cursor is a count: each write numbered as it comes; the file holder's is its memory's, not the file's
- holder calls are async (a file is); watch is not
- a link passes a refused write by (its cursor moves on) and keeps it in refused
- a link remembers every name each side gave or acked, and never sends those to it; the sets only grow
- back-pressure: since takes a limit, a link a limit per leg; one sync at a time, one more if poked meanwhile
- a holder that can't list has no since; link.fetch(node) asks both sides by get
- file holder: a CBOR list of writes, saved whole on each put and drop, read again before each save; loading only adds; no lock
- file holder: a save that fails refuses that put's new writes ("unwritable"), and they are not held
- Deno's file: written beside, then renamed over; the folder watched, events naming the file told
- web's file: written, not run; no FileSystemObserver, never told
- mirror: the whole value, one patch at the root; codec given (text: strict UTF-8, a BOM left in; cbor)
- mirror's echo: by bytes, the ones the file holds as far as it knows (last read or written)
- mirror opened: a file there goes into the graph; no file, the graph's value to the file; no value, the file left alone
- history's drop: its writes and heads let go of, the value stays; the next write there has no parents
- conformance: TypeScript only, files in memory; "experiments" added to the suite groups
- a file's access: a name (a path, a handle's name), read, write, watch; write takes a check (the bytes the file must still hold, or no file) and says whether it wrote
- the check is by bytes, the only true one both platforms have cheaply (a time and size can match after an edit). Deno: the file read after the one beside is written, just before the rename. web: read after the writable is written, before close (abort if changed). memory: compared in the write
- mirror refuses: a value is written only over what the mirror last read or wrote. changed (a save not heard yet): not written, and the file read in at once, as a hand edit would be. not held off: holding off ends the same (the watch reads it in later) but slower, and with no watch (web without FileSystemObserver) never; reading in now puts the person's bytes in the graph and its history, and the graph's write stays in history too, so nothing is lost either way. said: "the file changed since I last looked: not written; read in"
- mirror's write that throws: tried again after retry (1 s), then twice as long each time up to a minute, and on each new value; a success resets it. a hand edit meanwhile is read in over the value not written, said ("the file changed while I couldn't write; read in")
- mirror's file gone (deleted, or renamed: the same from here): the value stays; nothing written while it is gone (each value not written counted); a file there again is read in
- mirror's file that doesn't decode (not UTF-8): nothing written over it until it is edited into one that does, then read in
- two mirrors on one file: the mirror's path is one per file name, so start refuses the second ("taken"), nothing made; openMirror gives back { refused, at }. one at another at given, or one file under two names, is not seen
- a mirror and a link are processes (ermine/processes' start, nothing changed there), under the device's scope (the actor is its). the history is not: it has no state that changes (it records until stopped), only a record, so it is on a scope's node of its own (processes' scopes.ts) under the device's scope, gone with it
- where: a mirror at /system/mirrors/<the file's name, as one name (encodeURIComponent)>, or the at given; a link at /system/links/link-<8 hex>, or the at given (taken: throws). /system because a process is this device's work, and the node mirrored can be placed anywhere, many times or nowhere, so there is no one place beside it; a link joins two holders, not two places, but as a process it sits beside the others. reached by a walk (world.ts' places has processes' rows before children)
- state: each gives (inside.give) a computer whose value is its state { code, words, why? }; the value is written as the process node's value, so its status (ermine.computer.status) is the computer's: PENDING only until its first run, at start's pulse. a state changed: the computer's key marked, a pulse run. codes and words listed once, status.ts' STATES (lowercase-with-dashes); what differs each time (an error's message, the codec) in why
- records: what it has, counted or listed, on its node's attributes, ermine.sources.*: a mirror's file, mirrors (the node), unwritten; a link's known { a, b }, refused [{ name, node, why }]; the history's skipped. each written only when changed, with the node's scope open, its site the call into record
- a hand edit is made as the mirror's process: actor the device's, metadata { process: its path, node }; the path names the file
- a link runs in a graph it is given (createLink(a, b, { graph, at? })); the harness's: a's graph, else b's
- history: the host's rule records(id, part) (none: every string id, as before); it never records its own node. world.ts's rule: all but the process part (processes' rows: the running processes, never saved) and the nodes its scopes gave (processes' and the history's: the device's, now)
- JS accessors gone: mirror.trouble, link.status, history.skipped. a mirror and link give their process, the history its node's id; read with readState (the value) and readRecord (the attributes), tracked in a run

* found (for chee)
- drop and since don't meet: a link still knows the other side held what it dropped, so never sends it again; history's drop makes the next write a second root
- refused is two things: never (misnamed, the holder's say) and not now (a disk, a parent let go); a link can only pass by or stall, so not now is lost on that link
- an opaque cursor can't move partway: a batch partly refused either all moves on or all comes again
- table.del takes no header: a removal leaves the graph with no actor, time or site (on main 10-23: places makes one from the scope open, site table.del's caller; still none outside a scope, and a removal landed from elsewhere is told with none, or as the landing scope's)
- facts share values with entries written in place: a holder keeping them as given would see them change (not reproduced on main 10-23: unread copies a patch's value before writing under it)
- merging by playing again needs a part's history from its first write; the table can't list ids, so a late history has no base
- echo by a flag swallows a write to the same node and part made while a write lands (a watch writing back)
- a holder that can't list: a poke can't say which node, so there is nothing to ask it
- the mirror's whole-value write: a hand edit and a write elsewhere at once, one of them lost whole
- history as a holder: the graph's side of a link is one more holder, no special case
- the mirror's check has a window: a save landing between its last look and the rename (Deno) or close (web) is still written over. no lock an editor takes (Deno.flock is advisory), so it can only be narrowed
- reading in on a refusal is the last save winning: the person's bytes become the value, the graph's newer write only in history (the whole-value write again: a diff into patches would merge them)
- a process with no computer: start leaves ermine.computer.status PENDING on its node for as long as it runs. a mirror and link give a computer of their state for it; one with nothing to compute would give a computer of a constant
- deleted and renamed look the same through read, write and watch: a renamed file is not followed
- two mirrors are found by the path, one per file name: a mirror at another at, a symlink, a second path or another process is not seen (a lock, again)
- the host's rule is by id: a host has to remember which ids are its device's own (world.ts wraps scopes.give to). a node can't say it is local
